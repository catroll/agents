# 采集器起始日期要与来源历史对齐

2026-11-20，woody 的日报 CSV 从 2026-07-23 开始，而 Gmail 里从 2026-06-15 就有日报。原因有两条：
解析器要求标题里带 `YYYY-MM-DD`（7/23 前的标题没有），且旧标题以 `, 241 planned` 结尾、
正则也不接受。两者都是 7/23 的模板变更。脚本把 59 封旧邮件记成 `skipped`，文档写成
“更早的主题没有日期、无法确定归属”，缺口就被当成了已知限制，直到用户指出。

可推广的部分：**“跳过 N 条”是数据丢失的信号，不是结论**。采集类脚本交付前，把输出里最早的
一条和来源里匹配条件的最早一条对齐；对不上就说明解析器过严、过滤条件过窄，或来源确实更晚
（要有证据，不能靠推断）。

检查方式：对来源做一次宽条件搜索（这里用 `FROM coder@`，不依赖标题），取最早一封对照输出
首行；或把 `skipped` 的样本打印出来逐条判断是否真的该丢。注意标题模板会随时间变，正则要
兼容历史格式，而不是只匹配当前模板。
