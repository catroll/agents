# A backup generator looks complete but its own restore-side check disagrees

## Signal

`collect.sh` ran without a visible error, the tree had a directory per service, yet
`restore/restore.sh --check` reported `54 differ`, and `cmp` said
`…/config/…/config.yaml: 是一个目录` — the "backed-up config file" was a directory
named `config.yaml`, containing one file.

A second, separate defect: the manifest listed `channels.yaml.bak` as backed up, but
the copy step had excluded `*.bak`, so a restore would have looked successful while
copying nothing for that row.

## Root causes

1. A copy helper did `mkdir -p "$destdir"` where `destdir` was the *full file path*
   (`$dir/config$u`), then `cp "$src" "$destdir/"`. Correct for a directory source,
   wrong for a file source: it creates a directory named after the file. A helper
   that takes "the destination" must either take a directory and use `basename`, or
   branch on `-d "$src"` and use `dirname` for files.
2. The manifest was generated by walking the *source* paths. Entries reflected what
   was intended, not what was written. Generate manifests by walking the *copied
   tree* so an ignore list (`rsync --exclude '*.bak'`) cannot create phantom rows.

## Check that catches it

Build the restore/check side before trusting the collect side, and require
`0 differ, 0 missing` from a byte comparison against the live paths:

```bash
eqr/collect.sh && eqr/restore/restore.sh --check   # expect all identical
```

For a machine snapshot with root-only files, `--check` must distinguish
`MISSING` / `DIFF` / `UNREADABLE` — otherwise "412 identical, 0 differ" can be
reported while the root-only files were never read.

## Also seen: a pipefail abort truncates a generated file silently

Inside a `set -euo pipefail` script, `next=$(grep -F "$pat" file | head -1 | awk …)`
aborts the whole run when `grep` matches nothing (pipefail makes the pipeline exit 1).
The generator had already written the file header, so `SCHEDULE.md` ended mid-table
with exit 1 and no message near the failure. Append `|| true` to the pipeline, and
check the generator's own exit status directly (`./collect.sh; echo $?`) rather than
through `./collect.sh | tail`, which reports `tail`'s status.

## Negative result

`cp -a /etc/supervisor/conf.d` preserves the symlinks into the project trees, so the
backup points at live files and is useless after a reinstall. Use `rsync -aL` to
follow the links and store content, plus a `LINKS.txt` mapping name → original target.
